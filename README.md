# BidForge — 招投标智能体落地案例

> **前向部署工程师(FDE)客户落地案例。** 客户为一家传统招投标代理公司,客户信息与业务数据已脱敏。本仓库仅公开技术架构与决策记录,客户定制代码、知识库与真实数据保留在私有仓库。

## 一句话

把招投标代理公司的标书生产,从「人工 3–5 天/份」变成「多 Agent 管道 1.5 小时/份」。

## 背景与问题

传统招投标代理公司的三个真实痛点:

1. **标书周期长** — 每份标书需人工逐条响应招标文件,平均 3–5 天。
2. **文件不可复用** — 历史投标文件散落在各项目文件夹,无法检索、无法沉淀。
3. **废标靠人肉** — 评分标准、废标条款靠人工核对,漏一条即废标。

## 方案

四段确定性管道 + RAG 知识库 + 五门安全网关:

| 阶段 | 职责 | 产出 |
|------|------|------|
| Parse | 解析招标文件 | 结构化需求 |
| Write | 生成投标书 | 投标书正文 |
| Check | 合规审查 | 合规报告 |
| Guard | 安全门(5 gate) | 拦截 / 放行 |

详见 [docs/architecture.md](docs/architecture.md)。

## 效果

| 指标 | 改造前 | 改造后 |
|------|--------|--------|
| 标书周期 | 3–5 天/份 | 1.5 小时/份 |
| 文件管理 | 散落各文件夹 | 数据库检索 |
| 废标防控 | 人工核对 | 专门 Agent |

## 我的角色(FDE)

需求调研 → 架构设计 → 编码落地 → 部署 → 验收,现场交付。

## 技术栈

- **多 Agent 协同** AgentTeams
- **确定性编排** LangGraph
- **模型** DeepSeek(5 Agent 直连)
- **安全网关** MCP Guard(五门)
- **知识库** RAG(10 类 166 份领域文档)
- **对象存储** MinIO · **向量库** ChromaDB · **界面** Gradio
